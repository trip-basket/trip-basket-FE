# Travel Basket — UI/UX 명세

## 1. 개요

여행 일정을 실시간으로 공동 편집하는 웹 애플리케이션.
캘린더에 블록 형태로 일정을 배치하고, 지도에서 장소를 탐색하여 블록을 생성한다.

---

## 2. 영역 구분

### 2.1 공유 영역 (캘린더 + Bucket)

| 항목 | 설명 |
|------|------|
| 캘린더 | 날짜별 타임라인에 블록을 배치하는 공동 편집 영역 |
| Bucket | 아직 시간이 정해지지 않은 블록을 임시 저장하는 목록 |
| 공유 범위 | 같은 방(room)에 참여한 모든 사용자에게 실시간 동기화 |

### 2.2 개인 영역 (지도)

| 항목 | 설명 |
|------|------|
| 지도 | 장소를 검색하고 상세 정보를 확인하는 개인 도구. 추후 캘린더 블록의 장소를 지도에 표시하는 기능 추가 예정 |
| 공유 범위 | 본인에게만 표시. 다른 참여자에게 노출되지 않음 |

### 2.3 영역 분리 근거

- 캘린더와 Bucket은 모든 참여자가 동일한 상태를 봐야 하므로 항상 화면에 노출
- 지도는 개인 도구이므로 공유 영역과 시각적으로 분리되어야 "이 행동이 다른 사람에게 보이는가"를 사용자가 판단 가능
- 캘린더 블록의 장소를 지도에 표시하는 고도화를 위해, 캘린더와 지도는 항상 같은 화면에 공존해야 함

## 3. 레이아웃

### 3.1 데스크톱 (1024px 이상)

```
┌──────────────────────────┬───────────────────────┐
│ 캘린더 헤더               │                       │
│ ┌──────────────────────┐ │                       │
│ │                      │ │                       │
│ │  타임라인 그리드       │ │        지도            │
│ │  (가로+세로 내부 스크롤)│ │                       │
│ │                      │ │                       │
│ └──────────────────────┘ │                       │
│ ┌──────────────────────┐ │                       │
│ │ Bucket (가로 스크롤)   │ │                       │
│ │ [블록][블록][블록]→    │ │                       │
│ └──────────────────────┘ │                       │
│                          │                       │
└──────────────────────────┴───────────────────────┘
  ← 하나의 플로팅 박스 (50%) →  ← 지도 영역 (50%) →
```

- 왼쪽 플로팅 박스: 캘린더(상단, flex-1) + Bucket(하단, 가로 스크롤)
- 오른쪽: 지도 (나머지 공간)
- 추후 두 영역 사이에 드래그 리사이저를 추가하여 비율 조절 가능

**근거**:
- 캘린더와 지도가 항상 나란히 보여야 블록의 장소를 지도에 표시하는 고도화 대응 가능
- Bucket을 캘린더 아래에 배치하면, 캘린더와 지도 양쪽에서 드래그 거리가 비슷 (사이드바에 있으면 한쪽에만 인접)
- Bucket이 가로 스크롤이면 높이를 적게 차지하여 캘린더에 공간을 많이 확보
- 캘린더+Bucket이 하나의 플로팅 박스 안에 있어, 플로팅 박스 디자인과 일관성 유지

### 3.2 모바일 (1024px 미만)

```
┌─────────────────┐
│ 캘린더 헤더      │
│ ┌─────────────┐ │
│ │ 타임라인     │ │  ← 하나의 플로팅 박스
│ │ 그리드      │ │
│ └─────────────┘ │
│ ┌─────────────┐ │
│ │ Bucket →    │ │
│ └─────────────┘ │
└─────────────────┘

    [지도 보기]     ← 화면 하단 고정 버튼
```

지도 버튼 클릭 시 바텀시트로 지도 표시:

```
┌─────────────────┐
│ (캘린더 상단     │  ← 배경에 캘린더가 살짝 보임
│  살짝 보임)      │
├─────────────────┤
│ ── 드래그 핸들 ──│
│                 │
│   지도           │  ← 바텀시트 (화면 90%)
│   (검색바,       │
│    자동완성,     │
│    상세 정보)    │
│                 │
└─────────────────┘
```

- 캘린더+Bucket이 하나의 플로팅 박스 안에 세로 배치
- "지도 보기" 버튼은 화면 하단 중앙에 고정 (스크롤해도 동일 위치)
- 지도는 **바텀시트**(화면 90%)로 표시. 드래그 핸들을 아래로 내리거나 백드롭 클릭으로 닫음

**바텀시트를 선택한 근거**:
- 전체 화면 오버레이는 캘린더와의 맥락이 완전히 단절됨. 바텀시트는 상단에 캘린더가 살짝 보여 현재 컨텍스트를 유지
- 추후 "일정 상세 → 지도에서 보기" 흐름에서, 바텀시트는 일정의 부가 정보라는 계층 관계를 자연스럽게 표현
- 장소 탐색(검색바, 자동완성)과 일정 확인(마커 표시) 두 용도를 바텀시트 하나로 통합. 진입 경로가 하나여야 "지도는 아래에서 올라온다"고 학습하기 쉬움
- 바텀시트 높이가 90%이므로 검색바, 자동완성, 상세 정보 등 조작 UI를 충분히 수용

## 4. 블록 생명주기

### 4.1 블록 생성 경로

```
지도에서 장소 선택
        │
        ▼
   상세 정보 표시
        │
        ├─→ "Bucket에 추가" ─→ Bucket에 블록 생성
        │
        └─→ "일정에 추가"  ─→ 날짜/시간 선택 ─→ 캘린더에 블록 배치
```

### 4.2 "Bucket에 추가"

- 한 번 클릭으로 즉시 추가
- 토스트 알림으로 추가 완료 피드백
- 시간 정보 없이 장소명, 위치 정보만 저장

**근거**: Bucket은 "나중에 일정에 넣을 장소"를 모아두는 곳이므로 시간 정보가 불필요하다. 추가 과정에 마찰이 없어야 장소 탐색 흐름이 끊기지 않는다.

### 4.3 "일정에 추가"

- 날짜 선택 → 시간 슬롯 선택 단계를 거침
- 캘린더에 블록이 즉시 배치됨
- 지도는 열린 상태 유지 (연속 추가 가능)

**근거**: 캘린더에 배치하려면 날짜와 시간이 필수이므로 선택 단계가 필요하다. 지도를 닫지 않아야 "장소 탐색 → 추가"를 반복하는 흐름이 매끄럽다.

### 4.4 Bucket → 캘린더 이동

- Bucket 내 블록을 캘린더 타임라인으로 드래그 앤 드롭
- Bucket이 캘린더 바로 아래에 있으므로 드래그 거리가 짧음

**근거**: Bucket과 캘린더는 같은 플로팅 박스 안에 있어 드래그 앤 드롭이 자연스럽다.

### 4.5 캘린더 내 블록 조작

- 블록을 드래그하여 시간대 변경
- 블록 상하 가장자리를 드래그하여 지속 시간 조정
- 모든 조작은 실시간으로 다른 참여자에게 동기화

## 5. 공유/개인 경계 표시

### 5.1 시각적 구분

| 영역 | 표시 방법 |
|------|-----------|
| 캘린더 헤더 | 참여자 아바타 + "공유 캘린더" 라벨 |
| Bucket 헤더 | "장소 목록" 라벨 |
| 지도 | "내 지도" 라벨, 배경 톤 차별화 |

### 5.2 근거

- 실시간 커서가 없으므로, 영역 자체에 공유 여부를 명시해야 사용자가 "이 행동이 다른 사람에게 보이는가"를 판단 가능
- 라벨 + 색상 톤 차이로 최소한의 시각적 비용으로 구분 가능
- 실시간 커서는 추후 캘린더 영역에만 추가하면 공유 인지를 더 강화할 수 있음

## 6. 컴포넌트 구조

```
RoomContent
├── RoomDesktop (lg 이상)
│   ├── [플로팅 박스]
│   │   ├── Calendar        ← 공유
│   │   └── BlockBucket     ← 공유 (가로 스크롤)
│   └── Maps                ← 개인
│
└── RoomMobile (lg 미만)
    ├── [플로팅 박스]
    │   ├── Calendar        ← 공유
    │   └── BlockBucket     ← 공유 (가로 스크롤)
    ├── MapButton           ← 하단 고정 버튼
    └── BottomSheet         ← 개인 (바텀시트, 화면 90%)
        └── Maps
```

**근거**: 모바일과 데스크톱의 레이아웃 구조가 근본적으로 다르므로 (세로 스택 vs 가로 배치, 전체화면 오버레이 vs 나란히 배치) 뷰포트별 컴포넌트를 분리한다. Calendar, BlockBucket, Maps는 양쪽에서 공유하여 로직 중복을 방지한다. Calendar와 BlockBucket은 외부 래퍼(플로팅 박스)를 갖지 않고, 부모가 컨테이너를 제공하여 레이아웃 관심사를 부모에 위임한다.
